简介#

UE的**Module（模块）**系统是代码组织的核心。一个Project或Plugin至少包含一个Module，也可按需扩展。单Module独立编译的特性可显著减少迭代时的编译时间。

Module分为Public（对外接口）和Private（内部实现）部分。

  • 依赖管理：依赖分为Public和Private。应优先使用PrivateDependencyModuleNames并配合前向声明（Forward Declaration），以减少头文件包含，加快编译。

  • 主程序模块：

  • 若模块不被外部依赖（如游戏主程序），可将源码和头文件全部置于Private目录或Module根目录下。

#include "Modules/ModuleManager.h"

编译与构建#

虚幻构建工具（UBT）仅编译依赖链中的模块。若某模块未被任何活动的Build.cs引用，将被跳过以优化构建速度。

// ModuleRules.cs

// List of modules names (no path needed) with header files that our module's public headers needs access to, but we don't need to "import" or link against.  
public List<string> PublicIncludePathModuleNames = new();

// List of modules name (no path needed) with header files that our module's private code files needs access to, but we don't need to "import" or link against.  
public List<string> PrivateIncludePathModuleNames = new();

// List of all paths to this module's internal include files, not exposed to other modules (at least one include to the 'Private' path, more if we want to avoid relative paths)  
public List<string> PrivateIncludePaths = new();

// (This setting is currently not need as we discover all files from the 'Public' folder) List of all paths to include files that are exposed to other modules  
public List<string> PublicIncludePaths = new();

基于 UE5 的构建规则，这四个变量主要控制编译器如何寻找头文件以及模块间的依赖传递。核心区别在于“是否链接库”和“路径的作用域”。

  1. ...IncludePathModuleNames 系列

只包含头文件，不链接库（.lib/.dll）。

这两个变量用于当你需要使用另一个 Module 的类型定义（如 Enums、Structs、Templates），但不需要调用其具体的函数实现时。

  • PublicIncludePathModuleNames

    • 作用：将目标 Module 的 Public 目录加入到编译包含路径中。

    • 范围：Public。如果 Module A 依赖你的 Module，那么 Module A 也能找到这些目标 Module 的头文件。

    • 场景：你的公开头文件（.h）里引用了目标 Module 的类型。

  • PrivateIncludePathModuleNames

    • 作用：同上，将目标 Module 的 Public 目录加入包含路径。

    • 范围：Private。仅限当前 Module 内部使用，不会传递给依赖你的其他 Module。

    • 场景：你的私有代码（.cpp 或 Private/*.h）需要目标 Module 的类型，或者通过 FModuleManager 动态加载模块（如 AssetTools）以避免循环依赖。

  1. ...IncludePaths 系列

手动添加具体的文件夹路径到编译器的搜索列表。

这两个变量用于处理非标准目录结构，或者简化 #include 的书写长度。

  • PrivateIncludePaths

    • 作用：告诉编译器在编译当前 Module 时，除了标准目录外，还要去哪里找头文件。

    • 场景：简化内部引用。例如，若源文件在 Private/Sub/Deep/MyFile.h，将其父目录加入此列表后，代码中只需写 #include "MyFile.h" 而非完整路径。

  • PublicIncludePaths

    • 作用：告诉依赖当前 Module 的外部模块，去哪里找你的公开头文件。

    • 现状：在 UE5 中通常不再需要。

    • 场景：现在的 UBT（Unreal Build Tool）会自动扫描 Public 文件夹。只有当你的公开头文件放在非标准的自定义文件夹（即不在 Public 目录下）时，才需要手动配置此项以暴露给外部。

总结#

  • 带 “ModuleNames” 的是引用别的模块（只引头文件，不链接）。

  • 带 “Paths” 的是配置文件夹路径（告诉编译器去哪找文件）。

  • Public 会传递给依赖者，Private 仅限自己使用。
