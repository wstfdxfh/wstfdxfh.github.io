树#

  • 完全二叉树节点数量和叶子节点数量关系

​ 在完全二叉树中，节点数量 $n$ 和叶子节点数量 $l$ 存在以下关系：

$$ l = \left\lfloor \frac{n+1}{2} \right\rfloor $$$$ l = n - \left\lfloor \frac{n}{2} \right\rfloor = \left\lfloor \frac{n+1}{2} \right\rfloor $$

  • 哈夫曼树的带权路径长度

    哈夫曼树的**带权路径长度（WPL）**是所有叶子节点的权值与其到根节点的路径长度乘积之和：

$$ \text{WPL} = \sum_{i=1}^{n} w_i \cdot d_i $$
其中，$w_i$ 是第 $i$ 个叶子节点的权值，$d_i$ 是该叶子节点到根的路径长度（边数）。

红黑树和平衡二叉树#

  1. 什么是平衡二叉树
  • 定义：平衡二叉树（Balanced Binary Tree）是一类特殊的二叉查找树（BST），要求左右子树的高度差不超过一定的范围（常见的是 AVL 树，其平衡条件是任意节点左右子树高度差 ≤ 1）。
  • 目的：保持树的高度接近对数级别 $O(\log n)$，从而保证插入、查找、删除操作的效率。
  1. 什么是红黑树
  • 定义：红黑树（Red-Black Tree）是一种自平衡二叉查找树，它在普通二叉查找树的基础上，给每个节点增加一个颜色属性（红或黑），并通过一组规则来维持树的“近似平衡”。
  • 红黑树规则：
    1. 每个节点要么是红色，要么是黑色；
    2. 根节点是黑色；
    3. 所有叶子节点（NIL，空节点）都是黑色；
    4. 如果一个节点是红色，则它的两个子节点必须是黑色（红色节点不能相邻）；
    5. 从任意节点到其所有叶子节点的路径上，黑色节点数量相同。
  1. 区别
对比点 平衡二叉树（AVL 树） 红黑树
平衡条件 严格，左右子树高度差 ≤ 1 较宽松，只保证黑高一致，整体“近似平衡”
查找效率 更好，树高度更低（趋近于完全平衡） 稍差，最长路径可能接近最短路径的 2 倍
插入/删除效率 调整频繁，需要旋转多次才能维持严格平衡 调整较少，旋转最多 3 次即可恢复平衡
应用场景 查找操作特别频繁，更新操作相对少 插入、删除操作频繁，需要整体性能均衡
典型应用 数据库索引中的 AVL 实现（较少见） C++ STL map、set，Java TreeMap、TreeSet
4. 总结
  • AVL 树：更“正统”的平衡二叉树，查找更快，但维护成本高。
  • 红黑树：牺牲部分查找性能，换取更高的插入/删除效率，应用更广泛。

void preorder(TreeNode* root) {
    if (!root) return;
    stack<TreeNode*> st;
    st.push(root);
    while (!st.empty()) {
        TreeNode* node = st.top(); st.pop();
        cout << node->val << " ";
        if (node->right) st.push(node->right);
        if (node->left) st.push(node->left);

}

判断图是否有恰好经过所有边/节点一次的路径/回路#

  1. 遍历所有边正好一次（欧拉问题）

欧拉回路（Eulerian Circuit）

  • 充要条件（无向图）：
    1. 图是连通的（忽略孤立点）。
    2. 所有顶点度数为偶数。
  • 充要条件（有向图）：
    1. 图是强连通（或者忽略零出度/零入度顶点的弱连通）。
    2. 每个顶点的入度 = 出度。

欧拉路径（Eulerian Path，不必回到起点）

  • 充要条件（无向图）：
    1. 图是连通的（忽略孤立点）。
    2. 0 或 2 个奇度顶点。
      • 若 0 个 → 存在欧拉回路。
      • 若 2 个 → 必有欧拉路径，起点/终点是这两个奇度点。
  • 充要条件（有向图）：
    1. 图是弱连通（忽略方向连通性）。
    2. 至多一个顶点 out−in=1，至多一个顶点 in−out=1，其余顶点 in=out。
      • 若全部 in=out → 欧拉回路。
      • 否则正好有一个 out−in=1（起点）和一个 in−out=1（终点） → 欧拉路径。
  1. 遍历所有节点正好一次（哈密顿问题） 哈密顿路径/回路（Hamiltonian Path/Cycle）
  • 没有简单的充要条件（这是 NP 完全问题）。
  • 但有一些充分条件（保证存在，但不一定必要）：
    • Dirac 定理：若无向图有 $n(\ge 3)$ 个顶点，且每个顶点的度数 $\ge n/2$，则存在哈密顿回路。
    • Ore 定理：若对任意两个不相邻的顶点 $u,v$，都有 $\deg(u)+\deg(v)\ge n$，则存在哈密顿回路。
    • Bondy–Chvátal 定理：Ore 定理的推广。

Dijkstra 算法#

核心思想： 贪心策略，每次从未访问节点中选出距离源点最近的节点，用它来松弛相邻节点。

实现步骤：

  1. 初始化距离数组 dist[]，源点为 0，其余为无穷大
  2. 维护一个"已确定最短路"的节点集合 visited
  3. 每次从未访问节点中取出 dist 最小的节点 u，标记为已访问
  4. 遍历 u 的所有邻居 v，做松弛操作：若 dist[u] + w(u,v) < dist[v]，则更新 dist[v]
  5. 重复直到所有节点都被访问

import heapq

def dijkstra(graph, start):
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    heap = [(0, start)]  # (距离, 节点)

    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(heap, (dist[v], v))
    return dist
  • 时间复杂度： 用优先队列优化后 O((V + E) log V)
  • 限制： 不能处理负权边

Floyd 算法#

核心思想： 动态规划，枚举所有中间节点 k，尝试用 k 作为中转来缩短任意两点之间的距离。

实现步骤：

  1. 初始化 dist[i][j]：相邻节点填边权，自身填 0，不相邻填无穷大
  2. 三重循环：外层枚举中间节点 k，内层枚举所有起点 i 和终点 j
  3. 松弛：dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

def floyd(n, edges):
    dist = [[float('inf')] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0
    for u, v, w in edges:
        dist[u][v] = w

    for k in range(n):          # 枚举中间节点
        for i in range(n):      # 枚举起点
            for j in range(n):  # 枚举终点
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist
  • 时间复杂度： O(V³)
  • 优势： 一次性求出所有节点对之间的最短路，且能处理负权边（但不能有负权环）

Prim算法：#

思路： 从任意节点出发，每次从"已选节点"到"未选节点"的所有边中，贪心选取权重最小的边，将新节点纳入 MST，直到所有节点都被覆盖。用优先队列维护候选边。

#include <vector>
#include <queue>
using namespace std;

// graph[u] = { {v, weight}, ... }
int prim(int n, vector<vector<pair<int,int>>>& graph) {
    vector<bool> inMST(n, false);
    // 优先队列：{weight, node}，小顶堆
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;

    pq.push({0, 0});  // 从节点 0 出发，代价为 0
    int totalCost = 0;
    int edgeCount = 0;

    while (!pq.empty() && edgeCount < n) {
        auto [cost, u] = pq.top(); pq.pop();
        if (inMST[u]) continue;

        inMST[u] = true;
        totalCost += cost;
        edgeCount++;

        for (auto [v, w] : graph[u]) {
            if (!inMST[v])
                pq.push({w, v});
        }
    }
    return totalCost;
}

// 并查集定义见后文
int kruskal(int n, vector<tuple<int,int,int>>& edges) {
    sort(edges.begin(), edges.end());  // 按权重升序
    DSU dsu(n);
    int totalCost = 0, edgeCount = 0;

    for (auto [w, u, v] : edges) {
        if (dsu.unite(u, v)) {
            totalCost += w;
            edgeCount++;
            if (edgeCount == n - 1) break;  // MST 已完成
        }
    }
    return totalCost;
}

// 并查集
struct DSU {
    vector<int> parent, rank_;
    DSU(int n) : parent(n), rank_(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);  // 路径压缩
        return parent[x];
    }
    bool unite(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;  // 已连通，加入此边会成环
        if (rank_[px] < rank_[py]) swap(px, py);
        parent[py] = px;
        if (rank_[px] == rank_[py]) rank_[px]++;
        return true;
    }
};

    std::unordered_set 的 Rehash 机制#

    什么时候触发 Rehash？#

    1. 自动触发（插入元素时）

    当插入元素后，负载因子（load factor）超过最大负载因子时，会自动触发 rehash：

    1

    load_factor = element_count / bucket_count

    默认 max_load_factor = 1.0，即平均每个桶超过 1 个元素时触发。

    Rehash 时做了什么？#

    rehash 的核心是重新分配桶数组，并将所有元素重新散列到新桶中，具体步骤：

    ① 分配新的桶数组

    新桶数量通常是满足条件的最小质数（各实现不同，但一般按 2× 左右扩容），确保：

    1

    new_bucket_count >= n / max_load_factor

    ② 重新计算所有元素的桶索引

    1

    new_bucket_index = hash(element) % new_bucket_count

    由于桶数变了，即使 hash 值不变，% bucket_count 的结果也会变。

    ③ 将所有节点迁移到新桶

    标准库的 unordered_set 通常用链地址法，每个桶是一个链表。rehash 时：

    • 遍历所有旧桶的链表节点
    • 将节点重新链接到新桶对应的链表中（实现上通常复用节点内存，不重新分配元素本身）

    **④ 释放旧桶数组

哈希表的散列函数的选择#

在整数哈希表中，一个常见做法是使用

$$ h(k) = k \bmod M $$

其中 M 是哈希表大小（桶数）。

问题在于如何选择 M 才能让哈希分布更均匀。通常会选取质数作为模数。

原因有三点。

  • 首先，可以避免模式冲突。如果 M 是合数，比如 10，那么所有尾数相同的数（如 17, 27, 37）都会落在同一个桶里，冲突严重；或者当输入是一串步长为 g 的数列，且 g 与 M 有公因子时，也会出现周期性冲突。而如果 M 是质数，就能打破这种模式，让很多具有简单规律的数据分布更均匀。

  • 其次，质数与开放寻址哈希（如线性探测、二次探测）相性好。当 M 是质数时，探测序列能够遍历所有桶，不会出现只能覆盖部分桶的情况，这样就能保证最终一定找到空位。

  • 最后，质数模运算在数论里能产生完整剩余系，能让输入分布的规律性“去相关”，整体上更加均匀。比如若 M=12，插入所有偶数只会落在一半的桶上；但如果 M=13（质数），插入所有偶数会均匀分布在所有桶里。因此，工程实践里哈希表大小常常取接近目标容量的质数，以减少冲突、保证探测完整、提高分布均匀性。

关于快速排序#

一、快速排序的基本思想

快速排序是 分治法（Divide and Conquer） 的典型应用，它的核心思想是：

  1. 选择基准（pivot）：从序列中选择一个元素作为“基准”。
  2. 划分（partition）：将序列划分为两个子区间：
    • 左边子区间：小于等于基准的元素
    • 右边子区间：大于基准的元素
  3. 递归排序：对子区间分别递归地应用快速排序，直到区间长度为 0 或 1（此时有序）。

二、快速排序的实现步骤

void quickSort(vector<int>& arr, int left, int right) {
    if (left >= right) return;
    
    int pivot = arr[left]; // 选取基准，这里取左端点
    int i = left, j = right;
    
    while (i < j) {
        while (i < j && arr[j] >= pivot) j--; 
        while (i < j && arr[i] <= pivot) i++;
        if (i < j) swap(arr[i], arr[j]);
    }
    swap(arr[left], arr[i]); // 基准归位
    
    quickSort(arr, left, i - 1);
    quickSort(arr, i + 1, right);
}
  • 划分（Partition） 是核心。划分完成后，基准元素处于正确的最终位置。
  • 子问题递归解决，整个数组即可排好序。

三、时间复杂度与空间复杂度

  • 平均时间复杂度：O(n log n)
    • 每次划分相对均衡时，递归树高度约为 log n。
  • 最坏时间复杂度：O(n²)
    • 如果每次划分极不均衡（如选到的基准是最大或最小元素），递归树高度接近 n。
  • 空间复杂度：O(log n) ~ O(n)（取决于递归栈深度）。

为了避免最坏情况，常见优化有：

  1. 随机化基准选择（Randomized QuickSort）
  2. 三数取中法（median-of-three）
  3. 小区间切换到插入排序（当区间很小时用插入排序更快）

四、快速排序的特点

  1. 就地排序（In-place）：基本不需要额外空间（递归栈除外）。
  2. 不稳定排序：相等元素可能交换顺序。
  3. 平均性能非常优秀：在绝大多数情况下，快排比堆排、归并排序更快（常数因子小，cache友好）。

五、使用场景

快速排序的适用场景主要有：

  1. 大规模数据的排序
    • 快排的平均时间复杂度是 O(n log n)，且常数较小，适合对大量无序数据进行排序。
  2. 内存有限的场合
    • 与归并排序相比，快速排序是就地排序（in-place），不需要额外的 O(n) 空间。
  3. 需要高效的通用排序函数
    • 许多语言的库函数排序实现（如 C++ 的 std::sort）内部都基于改进后的快速排序（introsort：快排+堆排+插排的混合）。
  4. 数据随机分布
    • 对于随机分布的数据，快速排序几乎总能接近最优性能。

六、不适合的场景

  1. 数据接近有序时
    • 如果基准选择不好，容易退化到 O(n²)。此时可以使用归并排序或堆排序，或者对快排进行随机化改进。
  2. 需要稳定排序时
    • 快排不稳定。如果业务逻辑要求保持相等元素的相对次序，推荐归并排序或稳定的排序算法（如稳定版本的排序库函数）。
  3. 数据量较小
    • 数据很小时，插入排序反而更快，因为递归和交换带来的开销较大。

总结： 快速排序是一种 高效、通用、就地排序 算法，适合大多数随机分布的、对稳定性要求不高的大规模数据排序任务。它在编程语言库函数中常作为默认排序实现，但在需要稳定性或数据接近有序的场景下，应考虑归并排序或其他稳定排序。

时间复杂度#

计算时间复杂度使用的主定理：#

主定理（Master Theorem）标准形式

$$ T(n) = a \, T\!\left(\frac{n}{b}\right) + f(n), $$

其中：

  • $a \geq 1$ ：子问题的个数
  • $b > 1$ ：每个子问题规模缩小的比例
  • $f(n)$ ：划分与合并的额外代价

则有三种情况：

  1. $$ T(n) = \Theta\!\left(n^{\log_b a}\right). $$
  2. $$ T(n) = \Theta\!\left(n^{\log_b a} \log^{k+1} n\right). $$
  3. $$ T(n) = \Theta(f(n)). $$

游戏相关数据结构和算法#

A*算法#

A* 是一种带启发式的代价最小路径搜索。它在图/网格上寻找从起点 s 到目标 t 的最小总代价路径。核心思想是给每个中间节点 $n$ 定义一个评估函数：

$f(n)=g(n)+h(n)$

  • $g(n)$：从起点到 $n$ 的已知最小实际代价。
  • $h(n)$：从 $n$ 到目标的启发式估计代价（不可知未来的“预测”）。
  • 每次从开放表（open set）**里取 $f$ 值最小的节点扩展；扩展过的进**关闭表（closed set）。

只要启发函数满足一定条件（见下），A* 在找到目标时保证得到最优路径。

和“启发式搜索”的关系

  • “启发式搜索”是一个大类：用领域知识的估计函数指导搜索，减少盲目扩展。
  • A* 就是最典型的启发式搜索算法之一。它不仅“估”未来（$h$），还严格累计已知代价（$g$），在“贪心”与“稳妥”之间取平衡。

启发函数的两个关键性质

  • 可采纳性（admissible）：对任意节点 $n$，$h(n)\le h^*(n)$，即不高估到目标的真代价。满足此性质可保证 A* 最优。

  • 一致性/单调性（consistent）：对任意边 $n\to n'$，

    h(n) <= c(n,n′) + h(n′)h(n) <= c(n,n')+h(n')

    这相当于对估计值满足“三角不等式”。一致性 ⇒ 可采纳，并带来重要实现优化：一旦把节点以最小 $f$ 从 open 中弹出并放入 closed，它的最优 $g$ 已确定，无需“重开”。

和 Dijkstra 的关系

  • 当 $h(n)\equiv 0$（不用启发，只看已知代价）时，A* 就退化为 Dijkstra（也称“均匀代价搜索/Uniform-Cost Search”）。 结论：Dijkstra = A with $h\equiv 0$*。
  • 当所有边权都相等（如网格每步 1）且 $h\equiv 0$ 时，进一步退化为 BFS。
  • 当只看 $h$ 而忽略 $g$（即用 $f\!=\!h$），就是贪心最佳优先搜索（不保证最优，但往往很快）。
  • A* 介于两者之间：$h$ 越强（越接近真实代价、仍不高估），扩展越少；$h$ 过强且高估，则速度可能更快但会失去最优性。

原理与正确性要点

  • 直觉：A* 每次扩展“看起来总成本最有希望最小”的节点（已走的代价 + 对未来的乐观估计）。
  • 若 $h$ 可采纳，当 A* 第一次把目标节点 $t$ 从 open 中弹出时，就已找到全局最优路径。
  • 若 $h$ 一致，则各节点的 $f$ 值在其最优路径上非递减；因此节点一旦出队即确定最优 $g$，无需再次入队（实现更简单高效）。

A*(start, goal):
  open = min-heap keyed by f; push start with g=0, f=g+h(start)
  came_from = {}  // 记录最优前驱
  g[start] = 0

  while open 非空:
    n = pop_min_f(open)
    if n == goal:  // 终止条件
      return 重建路径(came_from, goal)

    对每个邻居 v:
      tentative_g = g[n] + cost(n, v)
      if v 未见过 或 tentative_g < g[v]:
        came_from[v] = n
        g[v] = tentative_g
        f[v] = g[v] + h(v)
        if v 不在 open: push(open, v)  // 一致启发下无需“重开”closed
  return 无解

复杂度

  • 时间：最坏情形指数级（搜索深度 d、分支因子 b ⇒ 近似 $O(b^d)$）。 但好的 $h$ 可极大削减扩展节点数。
  • 空间：要保存 open/closed，内存通常是瓶颈（近似 $O(b^d)$）。
  • 不可用情形：负权边（会破坏最短路的最优性保障；需用 Bellman-Ford 等）。

启发函数的设计与示例

  • 网格寻路
    • 4 邻接（上下左右，单位代价）：$h$=曼哈顿距离 $|x-x_t|+|y-y_t|$（可采纳且一致）。
    • 8 邻接（含对角，直走 1、对角 $\sqrt{2}$）：$h$=Octile（或 Chebyshev 变体）。
    • 连续空间：欧几里得距离。
  • 地图/道路网络：
    • 直线距/球面测地距；
    • Landmark + Triangle（ALT）、多源势函数等高级启发。
  • 拼图/滑块类（8-puzzle、15-puzzle）：
    • 曼哈顿距离、线性冲突（linear conflict）；
    • Pattern Database（模式数据库）：预计算子问题最优代价，查询取 max 合并（dominance 原理）。
  • 规划/调度：分解任务的不可少操作数下界、松弛问题的最优值等。
  • 组合启发：多个可采纳启发 $h_1,h_2,\dots$ 的逐点最大值 $h=\max_i h_i$ 仍可采纳且通常更强；求和一般会破坏可采纳性。

#include <bits/stdc++.h>
using namespace std;

// ===== A* on 4-neighbor grid with Manhattan heuristic =====

struct State {
    int f, g, x, y; // f=g+h
};
struct Cmp {
    bool operator()(const State& a, const State& b) const {
        if (a.f != b.f) return a.f > b.f;   // f 小优先（最小堆）
        return a.g < b.g;                   // tie-break：g 大优先
    }
};

static const int INF = 1e9;
static const int dx[4] = {1, -1, 0, 0};
static const int dy[4] = {0, 0, 1, -1};

int heuristic(int x, int y, int gx, int gy) {
    return abs(x - gx) + abs(y - gy); // 4邻接下的可采纳、一致启发
}

vector<pair<int,int>> reconstruct_path(
    const vector<vector<pair<int,int>>>& parent,
    int sx, int sy, int gx, int gy)
{
    vector<pair<int,int>> path;
    if (parent[gx][gy].first == -1) return path; // no path
    int x = gx, y = gy;
    while (!(x == sx && y == sy)) {
        path.push_back({x, y});
        tie(x, y) = parent[x][y];
    }
    path.push_back({sx, sy});
    reverse(path.begin(), path.end());
    return path;
}

// 返回路径坐标序列（含起终点）；若无路返回空
vector<pair<int,int>> astar(
    const vector<string>& grid, int sx, int sy, int gx, int gy)
{
    int n = (int)grid.size();
    int m = (int)grid[0].size();

    vector<vector<int>> g(n, vector<int>(m, INF));
    vector<vector<pair<int,int>>> parent(n, vector<pair<int,int>>(m, {-1, -1}));
    priority_queue<State, vector<State>, Cmp> pq;

    g[sx][sy] = 0;
    pq.push({heuristic(sx, sy, gx, gy), 0, sx, sy});

    while (!pq.empty()) {
        State cur = pq.top(); pq.pop();
        int x = cur.x, y = cur.y;
        if (cur.g != g[x][y]) continue; // 跳过过期状态
        if (grid[x][y] == '#') continue; // 障碍安全检查
        if (x == gx && y == gy) {
            // 找到最优解（h 一致时：pop 出即最优）
            return reconstruct_path(parent, sx, sy, gx, gy);
        }

        for (int k = 0; k < 4; ++k) {
            int nx = x + dx[k], ny = y + dy[k];
            if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;
            if (grid[nx][ny] == '#') continue;
            int ng = g[x][y] + 1; // 单位边权
            if (ng < g[nx][ny]) {
                g[nx][ny] = ng;
                parent[nx][ny] = {x, y};
                int h = heuristic(nx, ny, gx, gy);
                pq.push({ng + h, ng, nx, ny});
            }
        }
    }
    return {}; // 无解
}

int main() {
    // 示例网格：'.' 可走，'#' 障碍
    vector<string> grid = {
        "..........",
        "..####....",
        "..#..#....",
        "..#..#....",
        "..#..####.",
        "..#.......",
        "..######..",
        ".....G....",
        "....###...",
        "S........."
    };

    // 找 S 与 G
    int n = (int)grid.size(), m = (int)grid[0].size();
    int sx=-1, sy=-1, gx=-1, gy=-1;
    for (int i=0;i<n;i++) for (int j=0;j<m;j++) {
        if (grid[i][j]=='S'){ sx=i; sy=j; grid[i][j]='.'; }
        if (grid[i][j]=='G'){ gx=i; gy=j; grid[i][j]='.'; }
    }
    if (sx==-1 || gx==-1) {
        cerr << "Start/Goal not found.\n";
        return 0;
    }

    auto path = astar(grid, sx, sy, gx, gy);

    if (path.empty()) {
        cout << "No path.\n";
    } else {
        // 绘制路径
        for (auto &p : path) {
            int x=p.first, y=p.second;
            grid[x][y] = '*';
        }
        grid[sx][sy] = 'S';
        grid[gx][gy] = 'G';

        for (auto &row : grid) cout << row << "\n";
        cout << "Path length (steps): " << (int)path.size()-1 << "\n";
    }
    return 0;
}
